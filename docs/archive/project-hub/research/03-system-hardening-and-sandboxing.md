# System Hardening, Privilege Separation & Sandboxing on Omarchy

_Research report · Omarchy Kids Mode · 2026-09-01 · status: draft_

Scope: what Omarchy actually ships at the boot/disk/login/session layers (verified against the `omacom/omarchy` repo, `quattro` branch = 4.0.x, and the `master` branch = 3.8.5), the threat model for a curious child on a parent's Omarchy machine, and which mitigations are realistic. Every claim carries an inline source tag `[S#]`; the Sources section records what was actually fetched and its status. Anything not verified is labelled as such.

---

## TL;DR

- **The blueprint's boot/disk assumptions are wrong.** Omarchy is not GRUB + separate ext4 `/home`. It is: mandatory LUKS full-disk encryption → single btrfs filesystem with subvolumes → **Limine** bootloader booting a **Unified Kernel Image** (`ENABLE_UKI=yes`, `CUSTOM_UKI_NAME="omarchy"`) from an *unencrypted* ESP mounted at `/boot`, with **Snapper** root-only snapshots wired into the Limine menu via `limine-snapper-sync`. Secure Boot and TPM must be **off** to install. [S3][S5][S6][S16][S18][S19]
- **Login is SDDM with permanent autologin.** Since the 3.x migration, Omarchy replaced its `seamless-login` helper with **SDDM** (Wayland greeter running Hyprland). The first-boot wizard writes `/etc/sddm.conf.d/autologin.conf` and the code comments say: *"Encrypted installs keep autologin permanently (the LUKS prompt is the auth boundary)."* It also enables `getty@tty1` and sets the **root password equal to the owner's password**. [S12][S20][S21]
- **Consequence for kids:** the whole security model collapses to "who knows the LUKS passphrase". A child who can boot the machine alone knows it, and with it a live USB gives full disk read/write (trivial root). Boot-level protection therefore needs UEFI admin password + boot-order lock (+ Omarchy's own *Direct Boot* to skip the Limine menu), not GRUB passwords. Limine has **no password feature**; it has `editor_enabled: no` and config-hash enrollment, neither of which Omarchy sets. [S16][S17][S33][S34]
- **Ctrl+Alt+Fn VT switching is hardcoded in Hyprland** (`CKeybindManager::handleVT`, checked before any user bind; not configurable). It can be neutralised only at the XKB level (`srvr_ctrl(no_srvr_keys)`, option `srvrkeys:none`) or by making VTs useless (`NAutoVTs=0`, `ReserveVT=0`, mask gettys, lock root). [S55][S56][S43][S42]
- **Recommended account model: (A) a separate unprivileged Unix user `kid`** with its own SDDM session whose Hyprland config is **root-owned and passed via `--config`** (exactly how Omarchy's own SDDM greeter launches Hyprland). A "kid mode toggle" inside the parent's session (model B) is UX only, never a boundary: same UID, same sudo timestamp, same polkit identity, same `hyprctl` socket. Multi-user is "not part of the design" per a maintainer (2025) but a community post says "Multi user support coming in 4.1" (2026-08-18). [S20][S30][S54]
- **Omarchy 4 config is Lua, not hyprlang.** All Hyprland config files are `~/.config/hypr/*.lua`; Omarchy exposes `hl.unbind("KEY")` and `omarchy_default_bindings = false`. Hyprland 0.56.x on Arch; its permission system (`ecosystem:enforce_permissions`, added in 0.49) covers `screencopy`, `plugin`, `keyboard`, `cursorpos`, `input-capture`. [S9][S24][S52][S54][S60]
- **The blueprint's bwrap command would not launch a GUI app at all** on Arch (no `/lib64` symlink → dynamic loader missing; no `/proc`, `/dev`, `/etc`, Wayland socket, GPU, audio, or `$HOME`). A working profile is given below. `fapolicyd` is **not packaged for Arch** (AUR search returns 0 results) — drop it. `noexec` on the kid's home is done with a bind-remount or a subvolume mount line, not a partition. [S35][S36][S46][S53]
- Tiered profiles proposed: **Basic** (kid user + polkit denies + noexec + root-owned session config), **Standard** (+ firmware password, Direct Boot, Limine editor off, autologin moved to kid, root locked, gettys masked, XKB VT-switch removal, Hyprland permissions, bwrap launchers), **Fortress** (+ Secure Boot with custom keys + Limine config hash, AppArmor via cmdline drop-in, homed/podman — all unsupported by Omarchy and update-fragile).

## Findings

### 1. Omarchy's real boot, disk and login stack

**Installer & disk.** The ISO offers full-disk or free-space install; "either way, the installation defaults to full encryption"; `Ctrl+C` on the disk confirmation switches to an unencrypted install. Two passwords exist on an encrypted install: the LUKS passphrase and the user/sudo password; both changeable via *Update > Password*. [S6][S3] The manual-install path uses archinstall with "btrfs (default structure: yes + use compression)", "LUKS + Encryption password", one superuser, and auto-login after decryption. [S5] archinstall's default btrfs structure is the `@`, `@home`, `@log`, `@pkg` subvolume layout (third-party install notes; not re-verified against archinstall source). [S69] The manual notes hibernation uses btrfs subvolumes and that the LUKS prompt cannot be typed on a Bluetooth keyboard. [S2][S6]

**Bootloader.** Limine has been the default since Omarchy 2.0; snapshots "are not available if you're on GRUB or systemd-boot". [S4] Omarchy's shipped `limine.conf` sets `default_entry: 2`, branding colours, `hash_mismatch_panic: no`, leaves `timeout` commented out, and does **not** set `editor_enabled`. [S16] `/etc/default/limine` (from `default/limine/default.conf`) sets `ESP_PATH="/boot"`; drop-ins in `/etc/limine-entry-tool.d/` set `ENABLE_UKI=yes`, `CUSTOM_UKI_NAME="omarchy"`, `ENABLE_LIMINE_FALLBACK=yes`, `FIND_BOOTLOADERS=yes`, `BOOT_ORDER="*, *fallback, Snapshots"`, `MAX_SNAPSHOT_ENTRIES=6`, and a `quiet splash … vt.global_cursor_default=0` cmdline. [S16] `omarchy-refresh-limine` **overwrites `/boot/limine.conf`** with the shipped default and reruns `limine-update` + `limine-snapper-sync` — any local hardening of that file is lost on refresh. [S17] The ESP (`/boot`, FAT) holds `limine.conf` and the UKI unencrypted; ArchWiki warns that anyone who can access that partition can alter these files "even with Secure Boot" unless checksums are enrolled. [S34]

**Limine security features.** Per Limine's own CONFIG.md: `editor_enabled` — "If set to `no`, the editor will not be accessible. Defaults to `yes` unless a config hash is enrolled. Unconditionally disabled when Secure Boot is active." `hash_mismatch_panic` is forced when Secure Boot is active. There is **no password option**. [S33] ArchWiki: `limine-enroll-config` (with `ENABLE_ENROLL_LIMINE_CONFIG=yes`) enrolls a checksum of `limine.conf` into the Limine EFI binary; afterwards "modifying limine.conf and forgetting to re-enroll" prevents boot, and "disabling Secure Boot does not help" — keep a fallback bootloader. [S34]

**Secure Boot / TPM.** "You must turn off Secure Boot and/or TPM in the BIOS. You have to turn these off to be able to install Omarchy." [S6] Community guides exist for Secure Boot with custom keys on Omarchy/Limine (unverified beyond search listing). [S67]

**initramfs / encryption hook.** Omarchy's mkinitcpio drop-in uses `HOOKS=(base udev plymouth keyboard autodetect microcode modconf kms keymap consolefont block encrypt filesystems fsck btrfs-overlayfs)` — the classic `encrypt` hook (cmdline `cryptdevice=`), not `sd-encrypt`; `btrfs-overlayfs` (from `limine-mkinitcpio-hook`) makes snapshot boots writable-in-RAM. [S19][S34] `omarchy-provision-owner` handles both `cryptdevice=` and `rd.luks`/crypttab roots and, on first boot, adds the owner's password as a LUKS key slot and kills the installer's temporary slot. [S12] Implication: TPM2/FIDO2 LUKS auto-unlock via `systemd-cryptenroll` would require migrating to `sd-encrypt` — outside Omarchy's supported path. Omarchy's FIDO2 setup covers **sudo and polkit only, "not unlocking your computer"**. [S10][S28]

**Snapshots.** Snapper config `root` only: `SUBVOLUME="/"`, `NUMBER_LIMIT="5"`, `TIMELINE_CREATE="no"`; timeline timer disabled; `limine-snapper-sync.service` enabled. [S18] Snapshots are created on every update and by `omarchy-snapshot create` (runs `sudo snapper …`); restore is `sudo limine-snapper-restore`; restoring affects root but "preserves `/home`" and leaves `~/.config` untouched. [S4][S17] Booting a snapshot is done from the Limine menu (no password beyond LUKS). `Setup > Direct Boot` adds an EFI entry pointing straight at the UKI so firmware boots without the Limine menu; snapshots are then reachable only by choosing Limine in the firmware boot menu; refused on American Megatrends and Apple firmware. [S4][S17] `Setup > Reset Computer` restores the installer's baseline snapshot (ISO installs only). [S3]

**Login: SDDM, autologin, TTYs.** Omarchy 3.x migrated from a compiled `seamless-login` helper + `omarchy-seamless-login.service` to SDDM: the migration installs `sddm`, writes `[Autologin] User=$USER`, disables the seamless-login unit, **enables `getty@tty1.service`**, and enables `sddm.service`. [S21] The greeter is Wayland: `CompositorCommand=start-hyprland -- --config /usr/share/sddm/hyprland.lua` (a minimal root-owned Lua config). The session entry `omarchy.desktop` runs `uwsm start -g -1 -e -D Hyprland hyprland.desktop`. [S20] On first boot, `omarchy-provision-owner` creates the user with `useradd -m -G wheel[,recorded groups] -s /bin/bash`, sets the user password **and the root password** to the same value, writes `/etc/sudoers.d/00-omarchy-wheel` (`%wheel ALL=(ALL:ALL) ALL`), writes `/var/lib/sddm/state.conf` and `/etc/sddm.conf.d/autologin.conf` (`Session=omarchy.desktop`), and keeps autologin **permanently on encrypted installs**; unencrypted installs get a one-shot autologin removed by a `Before=display-manager.service` unit. [S12] `sddm.conf(5)`: `Relogin` defaults to false, so after logout or a session crash the greeter appears rather than re-autologging. [S58] The troubleshooting manual tells locked-out users to press `CTRL+ALT+F2`, "login as root", and run `faillock --reset`. [S7]

**Lock screen, PAM, faillock.** Omarchy 4 uses its own Quickshell shell (`omarchy-shell lock`) with PAM service `omarchy-lock-password` (`pam_faillock preauth … deny=10 unlock_time=120`, `pam_systemd_home.so` optional, `pam_unix`), plus a fingerprint PAM service when enrolled. [S25] `/etc/security/faillock.conf` raises `deny` from 3 to 10; `system-auth` and `sddm-autologin` are patched the same way. [S13] `Super+Ctrl+L` locks; the lid switch and `XF86PowerOff` binds carry `locked = true`. [S8][S24] logind: `HandlePowerKey=ignore`. [S26]

**sudo.** `%wheel` full sudo; narrow `NOPASSWD` grants for wheel: `omarchy-dns Cloudflare|Google|DHCP`, `omarchy-theme-set-browser-policy <hex>`, `timedatectl set-timezone …`; `passwd_tries=10`. [S14] `omarchy-sudo-passwordless` writes `USER ALL=(ALL) NOPASSWD: ALL` for 15 minutes (self-expiring timer) and warns "Anyone or anything with access to your user account gets full root"; `omarchy-sudo-keepalive` refreshes the sudo timestamp every 60 s in the background. [S15][S3]

**Network, firewall, packages.** ufw: deny incoming, allow outgoing, LocalSend 53317 open, ufw-docker rules. [S22] Base packages include `networkmanager`, `docker` (+compose/buildx), `yay`, `sddm`, `hyprland`, `hyprland-guiutils`, `uwsm`, `plymouth`, `xdg-desktop-portal-hyprland`, `ufw`; **no** `flatpak`, `bubblewrap`, `firejail`, `apparmor`, `malcontent`. [S23]

**Hyprland config model (Omarchy 4).** Config is Lua: `~/.config/hypr/hyprland.lua` loads Omarchy defaults (`require("default.hypr.omarchy")` from `OMARCHY_PATH=/usr/share/omarchy`, root-owned) plus user override files `bindings.lua`, `monitors.lua`, `input.lua`, `looknfeel.lua`, `autostart.lua`. [S9][S27] `bindings.lua` documents `hl.unbind("SUPER + SHIFT + B")`, `o.bind(...)`, and `omarchy_default_bindings = false` / `omarchy_preinstalled_bindings = false` to drop all defaults. [S24] Window rules use `o.window(match, props)` (Lua wrapper over `hl.window`). [S24] Arch ships Hyprland 0.56.2; the Hyprland wiki notes hyprlang is deprecated as of 0.55. [S52][S54]

**Upstream stance on multi-user.** Discussion #532 (opened Aug 2025 for "a PC shared with kids"): maintainer sailoz — multi-user "is not part of the design"; community workarounds are SDDM/ly; on 2026-08-18 a commenter posted "Multi user support coming in 4.1!" citing DHH. [S30] The `agent-accounts` branch is about AI-provider subscription accounts, not Unix users. [S29]

### 1b. Threat model — what a child can actually do

| Threat | Reality on Omarchy today | Notes |
|---|---|---|
| (a) Boot a live USB | Disk is LUKS-encrypted, so the USB alone reads nothing. **But** the child must know the LUKS passphrase to boot the machine at all (mandatory FDE, permanent autologin). With the passphrase, a live USB opens the disk → edit `/etc/shadow`, `sudoers`, anything. The ESP is unencrypted regardless: `limine.conf` and the UKI can be replaced. | Only UEFI admin password + disabled USB/other boot + Secure Boot (custom keys) close this. [S3][S6][S16][S34] |
| (b) Bootloader menu / editor / `init=/bin/bash` | Limine's editor is **enabled by default** (Omarchy sets nothing). The kernel is a UKI with embedded cmdline; whether an editor edit can inject `init=/bin/bash` into a UKI entry needs a hands-on test (see Open Questions). Any such trick still hits the LUKS prompt inside the initramfs. | Mitigate with `editor_enabled: no` (re-apply after `omarchy-refresh-limine`), Direct Boot + firmware password, or config-hash enrollment. [S16][S17][S33][S34] |
| (c) Roll back a snapshot | Anyone at the Limine menu can **boot** a snapshot (overlayfs, changes discarded); **restore** needs `sudo limine-snapper-restore`. Booting a snapshot that predates the kid setup boots a root filesystem *without* the kid's restrictions and, if the parent's autologin was already present then, autologs into the parent's session. `/home` is not snapshotted. | Prune pre-hardening snapshots; or Direct Boot + firmware password; or set `MAX_SNAPSHOT_ENTRIES=0`/drop `Snapshots` from `BOOT_ORDER` (loses menu rollback). [S4][S16][S17][S18][S47] |
| (d) VT switch, log in as parent/root | Hyprland switches VT on `XF86Switch_VT_1..12` keysyms before user binds are consulted. `getty@tty1` is enabled by the SDDM migration; root login is enabled with the owner's password; autovt gettys spawn on tty2–6 by default. Brute force on a TTY is throttled by `pam_faillock` (10 tries / 2 min lockout). | XKB `no_srvr_keys` in the kid session; `NAutoVTs=0`, `ReserveVT=0`, mask gettys; `passwd -l root`. [S55][S56][S21][S12][S13][S43][S42] |
| (e) sudo / polkit prompts | Non-wheel → sudo denied. Polkit's admin identity is wheel, so a kid-triggered prompt asks for the **parent's** password; ten wrong guesses lock the parent's account for 2 minutes (a DoS the child can cause). If the parent enrolled FIDO2, `pam_u2f` is `sufficient` for sudo/polkit — a plugged-in key means no password at all. | Return `polkit.Result.NO` for the kid on sensitive actions so no prompt appears; parent unplugs the key. [S38][S13][S28] |
| (f) Install packages | `pacman` needs root; `yay` can download/build in `$HOME` but not install. `flatpak install --user` needs no polkit (system installs need `org.freedesktop.Flatpak.app-install`). Flatpak is not installed by default. | Keep flatpak absent, or manage with malcontent app filters; noexec home stops AppImages/built binaries. [S23][S45][S59][S49] |
| (g) Mount USB drives | udisks2's `filesystem-mount` is normally allowed for active local sessions; removable media mounts are executable unless denied. | Deny `org.freedesktop.udisks2.filesystem-mount*`, `encrypted-unlock*`, `loop-setup` for the kid. [S38][S59] |
| (h) Change network/DNS | NetworkManager actions live under `org.freedesktop.NetworkManager.*`; `nmcli`/`nmtui` and the shell's network panel use them. Omarchy's `omarchy-dns` switch is a wheel-only sudo rule. `resolvectl` per-link DNS changes are a separate `org.freedesktop.resolve1.*` surface if resolved is in use (not verified for Omarchy). | Prefix-deny NetworkManager actions for the kid (mirror of ArchWiki's prefix-allow rule). [S50][S14][S38] |
| (i) Kill/replace the shell, edit Hyprland config | The kid owns their session, `$HOME`, and the Hyprland IPC socket; `hyprctl keyword`/`reload` can undo any config-level lockdown. The Hyprland wiki: "Hyprland itself cannot enforce this; consult the documentation for your application sandbox." | Root-owned config via `--config`; no terminal/arbitrary exec for the kid; sandbox launchers that do not bind the `hypr/` socket dir. [S54][S20] |
| (j) Run downloaded binaries/AppImages/scripts | `noexec,nosuid,nodev` on the kid's home (and `/tmp`, `/var/tmp`, `/dev/shm`, `/run/user/UID` — verify each on the host) blocks `execve` of files there, including AppImages. Interpreters (`bash file`, `python file`) and the `ld.so ./binary` trick still run code; `noexec` is not an allow-list. | Combine with PATH/binary curation in a sandbox; `fapolicyd` is unavailable on Arch. [S41][S46][S53] |

Kernel notes: Arch's default `kernel.sysrq = 16` (sync only), so SysRq-K/B are already disabled. [S51] Unprivileged user namespaces are enabled on all official Arch kernels except `linux-hardened`, so `bwrap` works without setuid. [S41] Yama `ptrace_scope=1` is the default. [S41] Docker group membership is root-equivalent — never add the kid. [S23]

### 2. Account model options

**(A) Separate Unix user `kid` with its own Hyprland session — recommended.**
- Feasibility: SDDM already exists and its greeter lists users with uid ≥ 1000; a second `wayland-sessions/*.desktop` entry is exactly how Omarchy launches its own session. [S20][S58] Create with `useradd -m -s /bin/bash kid` (no `wheel`, no `docker`); `/etc/skel` seeds Omarchy's per-user files; `omarchy-provision-user` exists for the runtime steps skel cannot do, but a kid does not need agent-skill symlinks. [S27]
- Autologin: either keep the parent's autologin (parent boots, logs out via `omarchy-system-logout` → greeter → kid logs in) or move `[Autologin] User=kid Session=omarchy-kid.desktop` so the machine boots straight into the kid session and the parent authenticates at the greeter. Both are one drop-in file. [S12][S58]
- Session switching: Hyprland has no fast-user-switch; logout → greeter is the path (`uwsm stop`). `Relogin=false` means a crashed kid session returns to the greeter, not to a TTY. [S25][S58]
- Hardware: logind seat ACLs grant input/video/audio to the *active* session; do not add the kid to `audio`/`video`/`input` groups (ArchWiki: `audio` group "will break fast user switching"). [S48]
- Omarchy config: defaults are root-owned under `/usr/share/omarchy/default/hypr` (Lua modules); only `~/.config/hypr/*.lua` is user-writable — for the kid, bypass that entirely with `Hyprland --config /etc/omarchy-kids/hyprland.lua` from a root-owned session entry (Omarchy's greeter uses the same `--config` mechanism). [S20][S27]
- Precedent: users report running multiple users on Omarchy via SDDM/ly; upstream 4.1 may formalise this. [S30]

**(B) "Kid mode" toggle inside the parent's session — UX only.**
Same UID means same files, same sudo timestamp (default 5 min, extendable; `omarchy-sudo-keepalive` keeps it alive indefinitely; `omarchy-sudo-passwordless` opens 15-minute root windows), same polkit identity (wheel = admin; FIDO2 key present = no password), same browser profile, same `hyprctl` socket. A submap-based "kid submap" cannot demand a password to leave, and `hyprctl dispatch submap reset` undoes it. Hyprland's session-lock protocol only shows a lock surface; apps cannot run "inside" it. Use (B) only for supervised co-use with toddlers. [S15][S28][S38][S54]

**(C) systemd-homed or per-user btrfs subvolume.**
- homed: gives a per-user LUKS-encrypted home, auto-locks on suspend, storage `luks|subvolume|directory|fscrypt|cifs`; Omarchy's lock PAM already includes `pam_systemd_home.so`, so a homed user would authenticate at the lock screen. But a LUKS home cannot be autologged (the password *is* the key), SSH/`authorized_keys` need workarounds, and a dirty loopback after power loss can lock the user out. For a kid the isolation runs the wrong way (the parent wants visibility). Fortress-only, optional. [S39][S25]
- Subvolume: btrfs-specific options are filesystem-wide ("only the options for the first subvolume to be mounted will take effect"), but the VFS flags `noexec,nosuid,nodev` are per-mount, so either mount a dedicated subvolume via fstab `subvol=…,nosuid,nodev,noexec` or simply bind-remount a plain directory (`/home/kid /home/kid none bind,nosuid,nodev,noexec 0 0`). Snapper only snapshots `/`, so a kid subvolume changes nothing about rollback; Omarchy disables btrfs quotas. [S46][S18][S19]
- Verdict: **A**, with the kid home as a plain directory or nested subvolume plus a bind-remount; **C-homed** not recommended.

### 3. Mitigations with Arch/Omarchy specifics

**Groups.** Kid in no supplementary groups; never `wheel`, `docker`, `adm`, `storage`, `disk`, `uucp`. Polkit treats wheel as admin (`50-default.rules`); if the kid is not in wheel, prompts ask for an admin's password. [S48][S38]

**Polkit rules** (`/etc/polkit-1/rules.d/10-omarchy-kids.rules`, `root:polkitd`, reload `polkit.service`; sort early with a low number). Deny for `subject.user == "kid"` (or `subject.isInGroup("omarchy-kids")`): `org.freedesktop.udisks2.filesystem-mount`, `…-mount-system`, `…-mount-other-seat`, `…encrypted-unlock*`, `…loop-setup`; prefix `org.freedesktop.NetworkManager.`; `org.freedesktop.systemd1.manage-units`; `org.freedesktop.Flatpak.app-install`, `runtime-install`, `modify-repo`, `install-bundle`, `override-parental-controls*`; optionally `org.freedesktop.login1.power-off*`/`reboot*` (or allow — a child powering off is a feature). Verify IDs with `pkaction` on the host. [S38][S59][S50]

**noexec home on btrfs.** Bind-remount line in fstab (above) or a dedicated subvolume mount; also audit `/tmp`, `/var/tmp`, `/dev/shm`, `/run/user/<uid>` (systemd's tmpfs defaults do not include `noexec`; check `findmnt -o TARGET,OPTIONS`). ArchWiki warns `noexec` on home breaks Steam, Wine, PyCharm, .NET — irrelevant for the kid, relevant if the parent's home shares the flag. Note removable media mounted by udisks are executable unless denied. [S41][S46]

**logind / TTY.** `KillUserProcesses=yes` for the kid via `KillOnlyUsers=kid` (ends leftover processes on logout; `KillExcludeUsers` protects root by default). `NAutoVTs=0` and `ReserveVT=0` stop autovt gettys; mask `getty@tty1.service` (Omarchy enabled it) — keep one documented recovery path for the parent (SSH, or re-enable from a live USB). VT switching itself is compositor-hardcoded; remove the keysyms with an XKB option in the kid session (`input.kb_options = "srvrkeys:none"`, symbols variant `srvr_ctrl(no_srvr_keys)`; both the option name in `rules/base.xml` and the symbols file are verified). Ctrl+Alt+Fn will then produce plain `F1..F12` keysyms and Hyprland's `handleVT` never matches. [S43][S42][S21][S55][S56]

**Root and parent hygiene.** `passwd -l root` (Omarchy sets root's password to the owner's); parent uses `sudo` from their own session for `faillock --reset`. Make faillock persistent across reboots (`dir = /var/lib/faillock`) since "if your attacker can reboot the machine, it is more secure if locks persist". sudo: `Defaults timestamp_type=tty, timestamp_timeout=2` for the parent; avoid `omarchy-sudo-keepalive`/`omarchy-sudo-passwordless` while a child is around (the latter leaves a `99-omarchy-nopasswd-<user>` file until a timer removes it — and notes that after a reboot the file can outlive the timer). Unplug FIDO2 keys. [S12][S41][S44][S15]

**AppArmor.** Arch's default kernel supports it (`lsm=landlock,lockdown,yama,integrity,apparmor,bpf` parameter + `apparmor.service`), package `apparmor` 4.1.7 in extra; Omarchy does not ship it. On Omarchy the cmdline change goes into a `/etc/limine-entry-tool.d/*.conf` drop-in (`KERNEL_CMDLINE[default]+=…`) followed by `limine-update` (UKI rebuild). Profiles for kid apps must be authored (`aa-genprof`/`aa-logprof` need auditd). Fortress-only. [S40][S34][S52]

**fapolicyd.** No `fapolicyd` package exists in the AUR (info and search both return 0) and none in the official repos; the blueprint's RHEL-centric plan is not portable. Use `noexec` + polkit + curated `PATH`/binaries in a sandbox instead. [S53]

**Flatpak + malcontent.** Flatpak (1.18.2) sandbox permissions: `--share=network`, `--socket=wayland|x11|pulseaudio|session-bus`, `--device=dri|input|all`, `--filesystem=host|home|xdg-*`, `--talk-name=`; negatives `--unshare`, `--nosocket`, `--nodevice`, `--nofilesystem`; `flatpak override` applies them (system-level as root, `--user` per user). Caveat: many Flathub apps are "not effectively sandboxed by default"; `--socket=session-bus` "stops the filtering". The kid can write `--user` overrides for their own installation, so parent-set restrictions hold only if the kid cannot run the `flatpak` CLI/Flatseal (or if apps are installed system-wide and overrides are system-level; confirm override precedence on the host). malcontent (`extra/malcontent` 0.14.0, deps accountsservice+flatpak+polkit) stores per-user app filters/OARS thresholds in accountsservice; Flatpak consults libmalcontent (installation by OARS rating; running by blocklist), e.g. `malcontent-client set-app-filter timmy x-scheme-handler/http` blocks a Flatpak browser for that user. Nothing on Hyprland honours the filter except Flatpak itself — a kid launcher would need to query libmalcontent. [S45][S49][S52][S59][S70][S71]

**Bubblewrap.** `bubblewrap` 0.12.0 in extra (not installed by Omarchy); works unprivileged on Arch's kernel; drops all capabilities; `--unshare-all` = `--unshare-user-try --unshare-ipc --unshare-pid --unshare-net --unshare-uts --unshare-cgroup-try` (so `--unshare-net` in the blueprint is redundant); `--new-session` (setsid) or seccomp on `TIOCSTI` is recommended to stop terminal injection; `--die-with-parent` kills the tree with bwrap. [S35][S36][S41][S52]
*Evaluation of the blueprint's command* (`bwrap --ro-bind /usr /usr --ro-bind /lib /lib --tmpfs /home --unshare-all --unshare-net dosbox …`): it will fail before any GUI appears. On Arch `/lib`, `/lib64`, `/bin`, `/sbin` are symlinks into `/usr`; the sandbox root is empty, so `/lib64/ld-linux-x86-64.so.2` does not exist and every dynamically linked binary fails to exec (ArchWiki examples always add `--symlink usr/lib /lib64`). There is no `--proc /proc`, no `--dev /dev` (no `/dev/null`, no `/dev/dri` → no GPU, no `/dev/snd`), no `/etc` (fontconfig, `ld.so.cache`, `passwd`, locale, timezone), no Wayland socket (`$XDG_RUNTIME_DIR/wayland-1` + `WAYLAND_DISPLAY`), no PipeWire socket (`pipewire-0`, `pulse/`), and `--tmpfs /home` without `--dir $HOME` leaves DOSBox unable to create `~/.dosbox`; the game directory itself is not bound. Classic DOSBox is SDL1 (X11/XWayland); prefer `dosbox-staging` with SDL2 Wayland. [S35][S36]
*Working shape* (from ArchWiki's Wayland/PipeWire chromium and GNOME examples): `--ro-bind /usr /usr --symlink usr/lib /lib64 --symlink usr/lib /lib --symlink usr/bin /bin --ro-bind /etc /etc --proc /proc --dev /dev --dev-bind /dev/dri /dev/dri --tmpfs /home --dir "$HOME" --ro-bind /srv/kids/games /srv/kids/games --dir "$XDG_RUNTIME_DIR" --ro-bind "$XDG_RUNTIME_DIR/wayland-1" "$XDG_RUNTIME_DIR/wayland-1" --ro-bind "$XDG_RUNTIME_DIR/pipewire-0" "$XDG_RUNTIME_DIR/pipewire-0" --setenv WAYLAND_DISPLAY wayland-1 --unshare-all --new-session --die-with-parent dosbox-staging …`. Bind **only** the two sockets, never the whole `$XDG_RUNTIME_DIR` (that would expose Hyprland's `hypr/` IPC socket). Confirm the socket name with `echo $WAYLAND_DISPLAY` on the host. [S35][S54]

**Firejail.** `firejail` 0.9.80 in extra; a **setuid-root** binary (ArchWiki lists it among SUID privilege-escalation risks; mitigate with `force-nonewprivs yes`); profiles in `/etc/firejail`, user overrides in `~/.config/firejail` (a kid can add `.local` overrides unless the wrapper pins `--profile=` and ignores user config — verify); `firecfg` symlinks profiled apps into `/usr/local/bin`; optional AppArmor stacking. Simpler than bwrap for well-known GUI apps, but adds a setuid surface to a system whose child user is the adversary. [S37][S41][S52]

### 4. Hyprland-level lockdown

- **Root-owned config.** Kid session entry `/usr/local/share/wayland-sessions/omarchy-kid.desktop` with `Exec=uwsm start -- Hyprland --config /etc/omarchy-kids/hyprland.lua` (pattern copied from Omarchy's greeter and session files). Inside, set `package.path` to root-owned directories only, and either skip `require("default.hypr.omarchy")` or set `omarchy_default_bindings = false` and `omarchy_preinstalled_bindings = false` before requiring it. The Lua config is a full language executing inside the compositor — never let the kid own it. [S20][S24][S54]
- **Binds.** Keep a minimal set: launcher key, volume/brightness, maybe screenshot; do not bind `hl.dsp.exit()` (wiki recommends `hyprshutdown` anyway), `submap`, `pass`/`send_shortcut`, terminals, `omarchy-menu`, `Super+Esc` system menu. Omarchy's `XF86PowerOff` bind (`locked = true`) opens the system menu — drop it. `hl.unbind("KEY")` is case-sensitive and removes earlier registrations. Mouse move/resize are binds too (`mouse` flag); not defining them disables dragging. Flags relevant here: `locked` (works under a lock screen), `transparent` (cannot be shadowed), `dont_inhibit`. [S24][S54]
- **Submaps.** `hl.define_submap(name, fn, "reset")`; `hl.dsp.submap("reset")` returns to the global map; "If you get stuck… `hyprctl dispatch 'hl.dsp.submap("reset")'`" — i.e. the session owner can always leave a submap via IPC. [S54]
- **Window rules for kiosk-ish behaviour** (Lua `o.window`/`hl.window` props verified): `fullscreen`, `fullscreen_state = "2 0"` (internal fullscreen while the client believes it is windowed — the documented anti-presentation-mode trick), `maximize`, `tile`/`float`, `pin` (floating only), `no_focus`, `no_initial_focus`, `stay_focused` (for the launcher), `suppress_event = "fullscreen maximize activate activatefocus"`, `idle_inhibit`, `monitor`, `workspace`, `no_max_size`, `min_size`/`max_size`. No dedicated "immobile/no-resize" rule was found in the table; rely on undefined mouse binds. Omarchy's defaults already apply `suppress_event = "maximize"` to `.*`. [S54][S24]
- **Permissions.** `hl.config({ ecosystem = { enforce_permissions = true } })` (default false; needs `hyprland-guiutils`, which Omarchy installs); `hl.permission({ binary = "/usr/bin/…", type = "screencopy|plugin|keyboard|cursorpos|input-capture", mode = "allow|ask|deny" })`; permissions "are not reloaded on-the-fly and require a Hyprland restart for security reasons"; recommended `plugin` deny for `hyprctl` ("attacker could issue `hyprctl plugin load /tmp/…so`"); last-rule `keyboard` deny `.*` blocks unknown USB keyboards (rubber duckies); portals go through permissions too — allow `xdg-desktop-portal-hyprland` for `screencopy` if screen sharing is wanted. Introduced in Hyprland 0.49. [S54][S60][S61]
- **`hyprctl`.** The IPC socket is per-user under `$XDG_RUNTIME_DIR/hypr/`; the wiki states Hyprland cannot block its own owner — sandboxes must omit that directory. [S54]
- **Crash/exit behaviour.** Session end → SDDM greeter (Relogin=false), never a bare TTY; but VTs with gettys exist unless masked. `misc.allow_session_lock_restore = true` lets a crashed lock client be restarted instead of leaving the screen unlocked. Omarchy's `omarchy-crash-watch` user unit offers an AI diagnosis terminal on crashes — disable for the kid (`ConditionPathExists=!%h/.local/state/omarchy/toggles/crash-capture-off`, or do not enable Omarchy user units in the kid session). [S58][S54][S25]

### 5. Terminal sandbox for kids ("bwrap-term-shield")

- **rbash is not a boundary.** Verified restrictions: no `cd`, no setting `SHELL/PATH/HISTFILE/ENV/BASH_ENV`, no slashes in command names, no output redirection, no `exec`, no `enable`, no `command -p`, no `set +r`; and "when a command that is found to be a shell script is executed, rbash turns off any restrictions in the shell spawned to execute the script". Any editor/pager/interpreter in `PATH` escapes. Use it only for friendliness inside a real sandbox. [S57]
- **bwrap "toybox" shell (recommended core).** Root-owned wrapper: `--ro-bind /usr/lib /usr/lib --symlink usr/lib /lib64` plus **individual** `--ro-bind /usr/bin/{bash,ls,cat,echo,cowsay,sl,fortune,figlet,…}`, `--ro-bind /usr/share/{cowsay,fortune,…}`, `--proc /proc --dev /dev --tmpfs /home --dir $HOME`, `--unshare-all --new-session --die-with-parent --clearenv --setenv PATH /usr/bin --setenv HOME …`, then `bash --norc -r`. No `hyprctl`, `python`, `sudo`, editors, or `flatpak` inside. Curriculum growth = adding binaries to the allow-list. [S35][S36]
- **Pitfalls.** Arch's `fortune-mod` ships **no** offensive (`off/`) database, but the standard fortunes are adult-flavoured in places — build a kid DB with `strfile` and point `fortune` at it. `sl` and `cowsay` are safe. Network stays unshared unless a lesson needs it. Terminal emulator choice: Omarchy's terminals (Alacritty/Ghostty/Kitty) run *outside* the sandbox; only the shell is inside. [S52]
- **Custom kid REPL.** A small program implementing a toy command set on a virtual filesystem (quests, `say`, `train`, `draw`) is the safest and most age-appropriate for 5–8; run it under bwrap anyway.
- **Container.** Rootless podman/distrobox (user namespaces, same kernel mechanism as bwrap) gives a throwaway "real Arch" for 11+, reset on exit, `--network none`; heavier and adds a large package surface. Not for the first release.

| # | Threat | Mitigation | Residual risk | Effort | Omarchy-specific notes |
|---|---|---|---|---|---|
| 1 | Live USB boot | UEFI admin password; disable USB/network boot; lock boot order | Firmware reset (CMOS), vendor backdoors; ESP still unencrypted | S (manual) | Omarchy needs SB off, so ESP tamper-proofing is impossible without custom-key Secure Boot [S6][S34] |
| 2 | Kid knows LUKS passphrase | Parent types it; or kid-only machine accepts the risk; Fortress: TPM2/PIN via sd-encrypt migration | Shoulder-surfing; sd-encrypt is off Omarchy's path and may break on updates | S / L | `encrypt` hook + `cryptdevice=`; FIDO2 covers sudo/polkit only [S19][S10] |

| 6 | Polkit prompt guessing / parent lockout | Deny rules for kid (no prompt); persistent faillock dir; FIDO2 key unplugged | Parent DoS via 10 wrong tries elsewhere | S | faillock deny=10/120 s is Omarchy's default [S13][S38] |
| 7 | Package install | Not in wheel; deny Flatpak system actions; do not install flatpak | `yay` builds in `$HOME` (noexec stops running them); `flatpak --user` | S | Omarchy has `yay` and its own repo; no flatpak by default [S23] |
| 8 | USB mount / exec from media | Deny udisks2 mount/unlock/loop actions | Manual `mount` needs root anyway | S | — [S59] |
| 9 | Network / DNS change | Prefix-deny `org.freedesktop.NetworkManager.` | `resolvectl`, browser DoH (see network report) | S | `omarchy-dns` is wheel-only [S14][S50] |
| 10 | Edit Hyprland config / `hyprctl` | Root-owned `--config`; no terminal; sandboxes omit `hypr/` socket | Any exec primitive → `hyprctl keyword` | M | Lua config = code; Omarchy defaults are root-owned in `/usr/share/omarchy` [S20][S27][S54] |
| 11 | Run downloaded binaries/AppImages/scripts | noexec/nosuid/nodev bind on home + tmp dirs; curated `PATH` in sandbox | Interpreters, `ld.so ./bin`; no fapolicyd on Arch | S–M | Check `/run/user/<uid>` and `/tmp` flags on host [S41][S53] |
| 12 | Sandbox escape from GUI app | bwrap minimal binds (Wayland+PipeWire sockets only), `--new-session`, `--unshare-all`; Hyprland permissions deny `plugin`/`screencopy` | Wayland/GPU/PipeWire attack surface; app-specific portals | M | Omarchy has `hyprland-guiutils` so prompts work [S35][S54] |
| 13 | Parent leaves privilege lying around | `timestamp_type=tty`, short timeout; avoid keepalive/passwordless sudo; lock screen on leave (`Super+Ctrl+L`) | Human factors | S | Omarchy documents a 15-min NOPASSWD toggle and a keepalive script [S15][S8] |
| 14 | Kid session crash leaves unlocked state | SDDM `Relogin=false` → greeter; `allow_session_lock_restore`; disable crash-watch AI terminal | Getty on a VT unless masked | S | [S58][S25][S54] |

## Implications & recommendations

**Account model:** (A) separate `kid` Unix user + dedicated SDDM session with a root-owned Hyprland Lua config launched via `--config`. Treat (B) as a supervised-toddler UX layer only. Skip homed; use a plain directory or nested subvolume with a `noexec` bind-remount.

**Design principle:** on Omarchy the LUKS passphrase is the *only* boundary upstream intends; Kids Mode must add a second boundary at login (kid account, no autologin for the parent, or kid-autologin with the parent at the greeter) and a third at boot (firmware password + Direct Boot + editor off). Everything else is defence in depth around a child who legitimately runs code as `kid`.

**Tiered hardening profile**

| Tier | Contents | Who |
|---|---|---|
| **Basic** (S) | `kid` user, no groups; polkit deny pack; noexec bind on kid home; root-owned kid session config with minimal binds and window rules; parent keeps autologin and types LUKS; `passwd -l root`; parent sudo hygiene | Families with young children; parent always present at boot |
| **Standard** (M) | Basic + UEFI admin password & boot-order lock; *Setup > Direct Boot*; `editor_enabled: no` re-applied by a post-update hook; prune pre-hardening snapshots; autologin moved to `kid` (parent logs in at greeter); `NAutoVTs=0`/`ReserveVT=0`/mask `getty@tty1`; XKB `srvrkeys:none` in kid session; `enforce_permissions` with `plugin`/`screencopy` deny; bwrap launchers for every kid app; flatpak absent or malcontent-filtered; disable crash-watch/agent tooling in kid session | Kids who boot the machine alone (they know LUKS) |
| **Fortress** (L) | Standard + custom-key Secure Boot with Limine config-hash enrollment (blocks editor and ESP tampering; Omarchy-unsupported, update-fragile); TPM2/PIN unlock via sd-encrypt migration; AppArmor via limine-entry-tool cmdline drop-in with authored profiles; rootless podman terminal; optional homed | Shared machines with technically capable teens; accept maintenance burden |

**Omarchy-update resilience:** everything placed in `/etc/polkit-1/rules.d`, `/etc/systemd/logind.conf.d`, `/etc/sddm.conf.d`, `/etc/limine-entry-tool.d`, `/usr/local/share/wayland-sessions`, and `/etc/omarchy-kids/` survives `omarchy-refresh-*`; `/boot/limine.conf` does not — hook it via `~/.config/omarchy/hooks/post-update.d/` (directory verified in the repo tree). Track Omarchy 4.1's multi-user work and align rather than fork. [S17][S29][S30]

## Open questions for the community

1. With a UKI entry, can Limine's editor inject `init=/bin/bash` (systemd-stub honours a bootloader-supplied cmdline only when Secure Boot is off — which is Omarchy's required state)? Needs a hands-on test on real hardware.
2. Is Omarchy 4.1's multi-user support a first-class `omarchy user add` with per-user provisioning, and will it keep permanent owner autologin? Should Kids Mode wait for it or ship WS-1 now and converge?
3. Does `hyprctl keyword ecosystem:enforce_permissions false` (or `hl.config` at runtime) weaken permissions for the session owner, or is that blocked like config reloads? [S54 says config changes require restart]
4. Flatpak override precedence: can a `--user` override re-grant a permission removed at system level? Determines whether Flatpak lockdown holds when the kid can run `flatpak`.
5. Which tmpfs mounts on a stock Omarchy host are `exec` (`/tmp`, `/var/tmp`, `/dev/shm`, `/run/user/<uid>`)? Fold results into WS-1.
6. Does Firejail's config allow ignoring `~/.config/firejail` entirely for a given user (kid overrides)? If not, bwrap-only.
7. Should the kid session autologin (machine "belongs" to the kid) or should the parent's autologin stay and the child use the greeter? Family-model question that changes WS-1 defaults.
8. Is there appetite upstream for `editor_enabled: no` and a Limine post-refresh hook in Omarchy proper?
9. How should Kids Mode interact with Omarchy's AI-agent tooling (agents, `omarchy-sudo-passwordless`, crash-watch) — hard-disable in the kid session, or an age-gated allow-list?
